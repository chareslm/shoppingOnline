# 模块分工与边界

| 成员 | 负责模块 | 核心职责 |
| --- | --- | --- |
| 成员 1 | 身份、安全、后台与统计 | 账号认证、RBAC、用户资料与地址、设备/审计、管理后台基础框架、业务事件与指标口径、Git 管理 |
| 成员 2 | 商家与商家端 | 入驻、店铺、员工、客服及资质管理 |
| 成员 3 | 商品 | 类目、SPU、SKU、价格、库存、上下架、搜索、评价 |
| 成员 4 | 交易 | 购物车、结算、订单、支付、退款、状态机与并发安全 |
| 成员 5 | 聊天与消息 | 客服聊天、会话分配、消息中心与多渠道推送 |

## 成员 1 的接口边界

1. 统一身份中心负责登录、Token、角色、权限和数据范围判断；业务模块不得自行实现认证或信任客户端提交的主体 ID。
2. 商家身份、店铺关系及员工信息由商家模块维护；身份中心只保存账号、角色及授权关系。
3. 用户资料、地址、偏好及关注关系由用户模块维护；商家模块仅通过已定义接口访问必要的脱敏信息。
4. 管理后台的通用登录、路由守卫、菜单权限、审计与统计框架由成员 1 维护；各领域负责人实现本模块的管理页面和接口。
5. 统计模块消费标准化业务事件，不直接修改订单、商品或聊天等领域表。

## 跨模块约定

- 接口通过 OpenAPI 文档维护，放在 `docs/api/`。
- 数据库迁移采用版本化脚本，所有表统一包含创建时间、更新时间及必要的版本号。
- 商家 ID、用户 ID、管理员 ID 从认证上下文获取，不接受客户端任意指定的数据范围。
- 高风险操作（权限变更、冻结、库存调整、退款审核等）必须写入审计日志。
