# 综合电商平台需求基线

> 来源：项目管理员提供的《电商平台需求分析与技术方案》初稿（2026-08-01）。
>
> 本文件用于将需求基线随 Git 仓库保存。后续需求变更须更新本文件及相关接口、数据库或架构文档。

## 1. 项目目标与范围

建设一个支持多商家入驻的综合电商平台，服务普通用户、商家和平台管理员，完成商品经营、交易支付、互动内容和平台治理的完整闭环。

本期包含：

- 用户端（Web、Flutter Android App、微信小程序）：注册登录、浏览搜索、购物车、下单支付、退款、评价、关注、聊天、论坛和通知。用户 Web 同时承载商家工作台（添加商品、商品浏览、客服账号、用户沟通、订单）。
- 统一管理端：按登录身份分离系统管理员与平台管理员。系统管理员负责用户与角色、系统日志；平台管理员负责商家审核、商品审核、全部商品和消息发布。商家不再使用管理端登录。
- Flutter Android App 可按后续需求承载商家高频移动操作，但不另建一套账号、权限或业务规则。
- 平台服务：认证授权、搜索、库存、订单、支付、聊天、内容审核、推送、统计、日志监控。

本期建设用户 Web、Android App 和微信小程序；不建设自建资金清算、跨境税务和复杂仓储调度。支付使用第三方支付沙箱或模拟服务。

## 2. 终端与权限基线

一期终端包括用户 Web、Flutter Android App、微信原生小程序、统一管理端和服务端。普通用户与商家共用 `frontend-web`，登录时选择用户或商家身份；系统管理员（`SUPER_ADMIN`）与平台管理员（`ADMIN`）共用 `frontend-admin`，登录时选择对应管理入口。各终端共用账号、权限和服务端业务规则，不得产生不同库存、订单或退款口径。

权限采用 RBAC 与数据范围控制相结合：

- 普通用户仅可访问本人数据。
- 商家仅可访问本店数据；主账号可创建子账号并分配店铺角色。
- 管理员分为超级管理员、运营管理员、审核员、客服仲裁员和风控管理员。
- 权限编码使用“资源:动作”，如 `product:create`、`order:refund`、`forum:audit`。
- 前端菜单或按钮权限不构成安全边界，所有服务端接口必须鉴权。
- 封号、退款、权限变更等高风险操作要二次验证并写审计记录。

## 3. 领域模块与职责

1. 身份与权限：账号、登录、角色、权限、设备、Token、审计。
2. 用户：资料、地址、偏好、店铺关注关系。
3. 商家：入驻、店铺、员工、客服、资质。
4. 商品：类目、SPU、SKU、价格、库存、上下架。
5. 搜索：索引、检索、筛选、排序、搜索建议、热词。
6. 购物车：购物项、按商家分组、价格与有效性校验。
7. 交易：结算、主/子订单、订单项、状态机、超时关闭。
8. 支付：支付单、回调、对账、退款单。
9. 评价：评价资格、评价内容、商家回复、评分聚合。
10. 社区：论坛、评论、点赞、广告、举报。
11. 客服聊天：会话、客服分配、消息、已读、离线补拉。
12. 内容安全：敏感词、图片检测、审核任务、申诉。
13. 消息中心：模板、用户偏好、站内信、多渠道推送。
14. 统计：业务事件采集、实时聚合、离线报表、指标口径。

## 4. 关键业务规则

### 身份、商家和用户

- 支持手机号、邮箱或用户名注册登录，以及验证码和密码登录。
- Access Token 短有效期；Refresh Token 可撤销，并支持设备管理。
- 密码只保存 Argon2id 或 bcrypt 加盐哈希；连续失败触发验证码、限流或临时锁定。
- 商家入驻提交店铺名称、主体信息、联系方式与资质；管理员审核后决定店铺状态。
- 店铺状态：待审核、正常营业、暂停营业、冻结、注销。
- 用户资料、地址、消息偏好及店铺关注关系必须按本人数据范围控制。

### 商品、搜索和评价

- 商品使用 SPU/SKU 模型，包含类目、品牌、规格、价格、库存、素材、详情、审核状态和修改记录。
- 商品从草稿、提交审核、审核通过、上架到下架遵循状态流转；修改受审字段会使原审核结果失效。
- 仅审核通过、已上架、库存正常且店铺正常的商品可被搜索和购买。
- 搜索支持关键词、纠错、同义词、建议、筛选、综合/销量/价格/好评率/上架时间排序；结果可秒级最终一致。
- 评价必须基于可信交易资格；好评率只统计有效评价，并设置最小样本门槛或平滑策略。

### 购物车、订单、库存、支付和退款

- 加入购物车不锁库存；结算时重新校验商品状态、价格、优惠、限购和库存。
- 一次结算形成总订单，并按商家拆分子订单；订单项保存商品、SKU、价格、图片和商家信息快照。
- 下单时在同一数据库本地事务中原子预占库存并创建待支付订单。禁止先查库存再普通更新。
- 库存权威在 MySQL：`available_stock`、`reserved_stock`、`sold_stock`；Redis 仅作展示缓存。
- 订单主状态：`PENDING_PAYMENT`、`PAID`、`FULFILLING`、`COMPLETED`、`CANCELLED`、`CLOSED`。
- 支付回调必须验签、校验金额和商户号，按支付流水幂等；前端支付结果不作为最终依据。
- 超时未支付关闭订单并释放预占库存；竞争失败返回具体缺货 SKU，不创建半完成订单。
- 退款使用独立状态机，累计退款不得超过订单项实际支付金额；退款成功后的库存处理必须可追踪。

### 互动、内容与消息

- 用户可以关注/取消关注店铺，并按偏好接收上新和补货通知；营销消息必须支持退订和频控。
- 一商家可有多个客服，客服存在在线/忙碌/离线状态、并发上限、技能组和会话分配策略；消息、转接和处理记录留痕。
- 聊天使用 WebSocket，保证会话内有序，支持已读回执、断线重连与离线补拉；图片/大文件不直接经 WebSocket 传输。
- 论坛、广告、评价、图片等内容经过敏感词、OCR/图片检测和人工审核；须保存审核版本、规则/模型版本、证据和申诉记录。
- 消息中心按模板、偏好、优先级、频控和渠道可用性进行投递；消费者使用幂等键、重试和死信队列。

### 统计与审计

- 从可信业务事件生成用户、商家、平台三个层级的统计数据。
- 实时看板允许分钟级延迟；财务对账通过离线精确计算。
- 每个指标明确统计时间、时区、去重规则、退款回溯规则和指标版本。
- 登录、权限变更、库存调整、退款、审核决策、管理员敏感查询等必须记录审计日志；关键审计日志只追加。

## 5. 非功能与安全要求

- 课程设计目标：普通查询 P95 不高于 300 ms，核心写接口 P95 不高于 500 ms，搜索 P95 不高于 800 ms。
- 核心一致性：库存原子预占、订单/支付幂等、Outbox 可靠事件；搜索、销量和评分可最终一致。
- 安全：HTTPS、参数校验、限流、Token 校验、XSS/CSRF/SQL 注入/SSRF/文件上传防护，以及 CSP、HttpOnly、Secure、SameSite 等浏览器策略。
- 隐私数据加密与脱敏；对象存储私有化并使用短期签名 URL；日志不得输出密码、Token、完整支付信息或完整隐私数据。
- 可观测性：统一错误码、日志格式、链路追踪 ID；采集指标、日志、链路，监控延迟、错误率、队列堆积与库存异常。
- 测试必须覆盖权限隔离、库存竞争、支付回调幂等、订单状态机、退款、注入/XSS/CSRF、恶意上传、消息重复/乱序及依赖短暂故障。

## 6. 技术与部署方向

- 后端：Java 21、Spring Boot 4.1、Spring Security、MyBatis-Plus、Bean Validation、OpenAPI 3。
- 前端：用户 Web 使用 Vue 3 + TypeScript；Android App 使用 Flutter；微信端使用原生小程序 + TypeScript；统一管理端使用 Vue 3 + TypeScript + Element Plus。
- 数据与中间件：MySQL 8.4、Redis、Elasticsearch；消息队列和对象存储仅在业务需求明确后接入，不作为当前开发前置条件。
- 运维：Docker Compose、Nginx、Prometheus + Grafana、Loki/ELK、OpenTelemetry、GitHub Actions 或同类 CI。
- 初期部署：单个 Spring Boot 模块化单体，并按需求逐步补充聊天、搜索、审核、通知等工作节点；课程设计阶段不提前拆分微服务。

## 7. 实施顺序

1. 第一阶段：账号认证与三级权限、商家/店铺/商品/库存、搜索、购物车、订单、模拟支付退款、管理后台、审计与基础安全测试。
2. 第二阶段：店铺关注、补货订阅、多客服聊天、评价、论坛广告举报和内容审核。
3. 第三阶段：排序与统计优化、多渠道推送、限流熔断、性能压测、可观测性、灾备和全量安全复测。

## 8. 项目管理员的工作内容

项目管理员负责第一个模块和 Git 管理，具体包括：

- 身份与权限：统一账号、注册登录、Token、角色、权限、数据范围、设备、账号安全和审计。
- 用户：个人资料、收货地址、偏好、店铺关注关系。
- 后台基础：管理员登录、权限菜单、用户/角色/权限管理、审计日志、全局统计框架；其他模块负责人在此框架中补充各自后台页面。
- 统计：业务事件采集、实时聚合、离线报表、指标口径和数据权限控制。
- Git 管理：分支策略、Pull Request、代码审核、冲突处理、版本发布和敏感信息防护。
