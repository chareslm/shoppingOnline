# V14 统计精确查询权限与索引

迁移文件：`database/V14__statistics_exact_query_permissions_and_indexes.sql`。

V14 创建 `statistics:platform:view` 和 `statistics:shop:view` 两项独立权限，分别初始授予 `SUPER_ADMIN` 与 `MERCHANT_OWNER`。客服和普通平台管理员不默认获得经营或平台统计权限。

迁移同时为用户创建时间、支付成功时间、退款完成时间、店铺商品状态和评价状态／创建时间增加组合或范围查询索引。第一阶段不创建统计聚合表，金额、订单、退款和商品指标继续直接读取 MySQL 权威业务表。

本地 V13→V14 升级和临时空库 V1→V14 全量迁移均已通过。`EXPLAIN` 已确认支付、退款和评价区间查询能够使用新联合索引，商品查询能够识别 `idx_spu_shop_status`；优化器仍可能根据选择性改用全表扫描或既有索引。后续索引调整必须通过更高版本迁移完成，不得修改已经执行的 V14。

## 代表性容量基线

2026-08-25 使用独立临时数据库完成运行时基线。数据包含 50,000 个普通用户、100 个店铺、10,000 个 SPU/SKU、200,000 笔订单／订单项／支付／搜索日志，以及 20,000 笔退款和评价，业务时间分布在 25 个自然日内。后端与 MySQL 均运行在同一台本地开发机，先预热 3 次，再对 4 个接口各串行采样 20 次：

| 接口 | 中位数 | P95 | 最大值 |
| --- | ---: | ---: | ---: |
| 平台概览 | 177.25 ms | 184.49 ms | 191.32 ms |
| 平台日趋势 | 226.36 ms | 236.65 ms | 238.13 ms |
| 商家概览 | 35.98 ms | 36.98 ms | 37.77 ms |
| 商家日趋势 | 35.47 ms | 37.24 ms | 39.18 ms |

`EXPLAIN ANALYZE` 的关键节点实测为：50,001 个用户的角色与状态聚合 55.7 ms；200,000 笔支付的平台聚合 83.3 ms；单店 2,000 笔支付聚合 8.0 ms；单店 2,000 条订单项销量聚合 13.7 ms。平台支付样本在整个区间内全部命中，优化器选择全表扫描而非低选择性的状态／时间索引，这是当前数据分布下的合理计划。

该结果是开发机容量基线，不等同生产服务等级目标；但在当前课程设计规模下没有引入缓存或统计汇总表的性能证据。数据量、时间跨度或并发模型发生明显变化后应重新采样，再决定是否进入日聚合阶段。
