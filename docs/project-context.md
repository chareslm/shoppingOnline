## 项目定位

本项目是五人协作完成的综合电商平台课程设计，面向用户购物、商家经营和平台治理。课程设计阶段采用模块化单体，避免过早拆分微服务。

## GitHub 分支与规则

```text
feature/* 或 fix/* → 项目管理员集成至 develop → Pull Request + 非作者批准 → main
```

- 项目管理员可直接推送或合并 `develop`；其他成员通过功能分支提交改动。
- `main` 必须通过 Pull Request，至少 1 位非作者成员批准且所有讨论已解决后才能合并。
- 两个分支均禁止强制推送和删除；`main` 的管理员绕过仅用于紧急或发布处理。

## 使用约定

1. 从 `develop` 更新后再创建自己的功能分支。
2. 提交后推送功能分支；项目管理员完成构建、测试、冲突和文档检查后集成至 `develop`。
3. `develop` 合并到 `main` 的 PR 作者不能审批自己的 PR，须由其他团队成员审核。
4. 高风险或跨模块改动须在提交说明或 `docs/` 中说明影响范围。
5. 任何 Secret、数据库密码、JWT 密钥、第三方 API Key、`.env` 或 `application-local.yml` 均不得提交。

## 下一阶段建议

统计模块先执行 `docs/architecture/statistics-foundation.md` 中的准入检查，不在商家数据范围和交易金额契约稳定前创建经营统计接口或聚合表。成员 2 需先提供权威店铺及账号—店铺关系；成员 3、4 需关闭店铺归属、价格、支付回调和跨店补偿边界并确认事件语义。条件满足后，统计模块先用 MySQL 权威表完成精确查询和人工对账，再增加日聚合、缓存和报表。用户 Web 已接入商品和交易页面，App 与小程序的商品、交易和消息页面继续等待各模块稳定契约。店铺关注关系同样等待商家模块契约，不创建临时接口或信任客户端 `shopId`。
